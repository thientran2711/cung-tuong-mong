### Fixes (numbered)
1. **BLOCKING — host's game drops the friend's choice (jnf, co-op).** jsmg chooseM wrapper sets `S.nfX.st="mg"` on the host while her game is open. jnf's co-op handler accepts the friend's choice only when `x.st==="open"` (jnf.js:336 `if(x&&x.st==="open"&&x.fr===undefined)`), and the guest sends "ch" only once (no resend). So a friend who picks during the host's game (the game lasts longer than the 10-s window) is dropped; when the host's game ends, step() sees `x.fr===undefined` and `Date.now()-x.myAt>choice.waitMs` → `x.fr=null` → the friend's Tranh sủng / Chặn ngự giá is lost (treated as Thôi). Fix: the friend's "ch" must also be taken while `st==="mg"` (e.g. the adapter wraps the COOP "act" listener / the check accepts "open"|"mg"), and the friend-timeout must not count the host's game time. Coordinate with D (jnf owner) if jnf itself changes.
2. **BLOCKING — the friend's own game win never reaches the resolve (jnf, co-op).** On the guest seat the game opens after `mine()` has already sent "ch" (`{v}` only, no rung). Her result row still tells her «cơ duyên lên Khá chắc» — a false promise. Fix: carry her rung to the host (e.g. "ch" sent after her game with `up`, or a second message with `up` that the host waits for, bounded) and give the host a token for `f` from it; same win/rung/cap rules (BAL.steal.mg).
