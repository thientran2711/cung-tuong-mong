## FAIL (1): KPMAX is per key for the WHOLE session and only the life cover resets it
kpShown() = max(KPMAX[key], now) with no reset. Only lPaint resets (KPMAX.life=0 when its bar element is rebuilt). The sổ panel («Tranh người trong kiếp này», key «fig», jload dlPanel, HTML form) is a SNAPSHOT opened again and again, not one running bar; first-load key «core» is once per session. My probe on the merged build (kitProgress called as dlPanel does):
- kitProgress({key:"fig",have:10,total:10}) → --v 100 %, «đủ cả»
- later kitProgress({key:"fig",have:0,total:20}) (a new life / new pictures wanted) → STILL 100 %, «đủ cả»; have 5/20 → 100 % «đủ cả».
So after the pictures were once all in, any later opening of the panel (new life, new figures wanted, or a cache clear) says everything arrived while it did not — a false statement (hint/UI must be true now). The owner's complaint (a LIVE bar must not fall / stall) does not need a session-long max for the panel.
Fix (jload only): forward-only only WITHIN one run: reset the key when a new run starts — dlPanel (and any snapshot caller) clears KPMAX.fig before kitProgress (or passes a fresh:true that skips the stored max), and key «core» is cleared when paint() starts a new load; keep the max for the running life cover. Add a check to kit-progress-run.js: 10/10 then 0/20 with the same key after a reset must show 0 %.
